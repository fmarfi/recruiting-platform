# Client meeting 02 (15 Nov 2026): report, actions, research

Source: the raw notes and three screenshots of the client's current Salesforce, kept outside git in `client-private/`. This report carries no client name and no real person or company data; screenshots are described by structure only.

## Summary

- This was the first real user input. The requirements and the 28 stories written before it were our own assumptions.
- The kanban board is not wanted. The users work from a longlist, in tables, the way they work in Excel today.
- The workflow should be driven from the candidate, and a candidate must be movable from one position to another.
- The team is small (3 to 5 users) with three real roles: researcher, consultant, sales.
- Fields for candidate, client and position are not settled: we send screenshots of our screens, they mark what they need.

## What we learned

| Topic | What the client said | Effect on what we built |
| --- | --- | --- |
| Kanban board | Not wanted; only the longlist part | Board hidden. The search page becomes a longlist table with a stage column |
| Candidate process | Must be more practical; drive the workflow from the candidate | Person page becomes the hub: add to a search, change stage, log activity from there |
| Move between positions | A candidate must be movable from one position to another | Not in the contract; needs a new endpoint and UI |
| Fields | We send screenshots of the candidate, client and position screens; they tell us which fields they need | Field and form changes wait for their answer |
| Roles | **Researcher**: runs the recruiting operation, enters data, builds the longlist, joins meetings with the consultant. **Consultant**: owns the search by expertise, enters contracts. **Sales team**: the client side | Differs from our consultant / manager / admin. Recorded; role gating stays deferred until after the pilot |
| Team size | 3 to 5 users | Collision and activity features stay light |
| Activity | Mostly valuable for bigger teams, to stop two people working the same contact | Lower priority; the existing `ACTIVE_IN_OTHER_PROCESS` warning may be enough |
| Agreements and proposals | Keep them separate, each with its own history; agreements are per position | `/agreements` exists since contract 1.3; there is no UI yet |
| Searches and contacts | A search is created on a contact of the client company | Their job record has a Contact field next to Account (see screenshots); check ours |
| Network map | Better placed inside the client | Org view on the client page instead of person-level links only |
| Home dashboard | Today's tasks; a period filter (last week, last 30 days); my own numbers (interviews held, CVs screened) | Contract 1.4 home has today / needs-you / search health but no personal numbers and no period. UI-B2 and UI-B3 are not built yet, so the change is cheap now |
| Excel | They normally work in Excel | Tables, inline edit, paste and export matter more than boards and cards |
| LinkedIn | The licence is very expensive; how can we differ? | Research topic. The no-scraping rule stands |
| AI | A model could run as an assistant | Phase 2 input |
| Unclear terms | Lead, CV push versus CV sent, Campaign history (used to win new business), Job opportunity | Follow-up questions plus research |

## What the screenshots show (structure only)

1. **Personal dashboard.** One dashboard with a date filter set to "last 30 days" and about ten number tiles, all scoped to the logged-in user ("My ..."): next tasks, internal interviews, client meetings or visits, leads, CVs sent, CVs pushed, candidates. Each tile is one count with a "view" link to the list behind it. This is the model for the Home screen they asked for.
2. **Recent items.** A list of recently opened records. A client company shows: record type (for example head-office site), segmentation (size class), phone, financial status, credit approval, last closing date. A contact shows: primary phone, e-mail, department.
3. **Position, general info.** Fields: job name, number of openings, remaining openings, employment type, account, contact, office, exclusive (yes/no), profession, İŞKUR profession code, profession name, internal job title, record type (for example permanent retained), job stage, remote job, live job.

What this adds:
- **Openings**: a position has a number of openings and remaining openings. Our assumption was one opening per search.
- **Contact on the position**: confirms "a search is created on a contact".
- **İŞKUR profession code**: suggests reporting duties as a licensed private employment agency. Needs a legal check.
- **Record type**: "permanent retained" implies other engagement types exist. Ask which.
- **CV sent and CV pushed are counted separately** on the dashboard, so the two are distinct events for them.

| Area we built | Verdict | Note |
| --- | --- | --- |
| Board per search | Drop | Hide it; keep the code until the pilot confirms |
| Longlist and shortlist | Keep | Becomes the main view of a search |
| Home (My day) | Change | Add period filter and personal numbers; keep today's tasks |
| Network links | Change | Show the map inside the client |
| Proposals | Change | Split agreements from proposals, each with history |
| One opening per search | Change | Number of openings and remaining openings |
| Roles | Change later | Researcher, consultant, sales; gating after the pilot |
| Quick log, next actions, client statuses, consent, CSV import | Not discussed | Raise next time |

## User stories captured

| # | Who | I want to | So that |
| --- | --- | --- | --- |
| 1 | Researcher | build and work a longlist for a search in one table | I do not need a board or a spreadsheet beside it |
| 2 | Researcher | move a candidate from one position to another | a good candidate is not lost when the first role does not fit |
| 3 | Researcher | run a candidate's process from the candidate's own page | I follow the person, not the search |
| 4 | Consultant | record an agreement for a position, separate from the business proposal | I can see proposal history and signed agreements apart |
| 5 | Consultant | create a search on a named contact of the client company | everyone knows who the search is for |
| 6 | Any user | see my own numbers for last week or the last 30 days (interviews, CVs screened, CVs sent, CVs pushed) | I know where I stand |
| 7 | Any user | see today's tasks when I sit down | I know what to do first |
| 8 | Sales | see the people map inside a client | I know who is who before I call |
| 9 | Sales | see campaign history | I can win new business from past outreach |
