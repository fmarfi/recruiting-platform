# A-12 - Network of people

**Priority:** Must  
**Requirement:** A-12 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a consultant, I want one record per person I know, with company history, how I know them, relationship owner and last contact, so that the firm's network lives in our own system.

## Acceptance criteria

1. **Create a person**
   - Given a signed-in user
   - When they create a person with name, type (EXECUTIVE, CLIENT_CONTACT, REFERRER, CANDIDATE), current company and title
   - Then the person exists with them as relationship owner by default and consent status NOT_SENT
2. **Company history**
   - Given a person with two former employers
   - When the person page is opened
   - Then current and former positions are listed with dates
3. **How we know**
   - Given the person form
   - When the user records "met at an industry dinner"
   - Then the text is saved in the how-we-know field and is shown on the person page
4. **Last contact**
   - Given a person with logged activities
   - When the list is sorted by last contact
   - Then order follows the latest activity date; people with none are last
5. **Change owner**
   - Given a person owned by consultant A
   - When a manager reassigns to B
   - Then the owner changes and the change is logged
6. **Duplicate warning**
   - Given a person with e-mail x exists
   - When another person is created with the same e-mail
   - Then the system warns and links to the existing record (no silent duplicate)

## Dependencies

Authentication and roles
