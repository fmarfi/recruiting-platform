# A-02 - Account status lifecycle

**Priority:** Must  
**Requirement:** A-02 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a consultant, I want to move an account through a defined status lifecycle, with every change logged, so that everyone knows where a client stands.

## Acceptance criteria

1. **Legal move**
   - Given an account in status LEAD owned by the consultant
   - When they change it to PROPOSAL_SENT
   - Then the status changes and a log entry records from, to, user and timestamp
2. **Illegal move**
   - Given an account in status LEAD
   - When a user tries to change it to ACTIVE
   - Then the change is rejected, the status stays LEAD, and the error lists the allowed targets
3. **Reason required**
   - Given an ACTIVE account and a manager
   - When they move it to ON_HOLD without a reason
   - Then the change is rejected with a reason-required error; with a reason it succeeds and the reason shows in the timeline
4. **Role limit**
   - Given a consultant who is not manager or admin
   - When they try to move an account to CLOSED
   - Then the change is rejected with a permission error
5. **Closing blocked by open jobs**
   - Given an account with a job order in SOURCING
   - When a manager moves it to CLOSED
   - Then the change is rejected and the open job orders are named
6. **History is append-only**
   - Given an account with 3 status changes
   - When the history is requested
   - Then 3 entries are returned in order and none can be edited or deleted
