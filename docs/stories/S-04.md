# S-04 - Data subject requests

**Priority:** Should  
**Requirement:** S-04 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a person whose data is stored, I want to request access, correction or deletion and have the request tracked, so that my KVKK rights are met.

## Acceptance criteria

1. **Log a request**
   - Given a person record
   - When any consultant, manager or admin logs a request of type ACCESS, CORRECTION, DELETION or OTHER with received date
   - Then it is saved with status RECEIVED and a due date 30 days after receipt
2. **Complete access**
   - Given an IN_PROGRESS ACCESS request
   - When a manager or admin triggers an export
   - Then a file with the person's data is produced and the request becomes COMPLETED with the date
3. **Deletion**
   - Given an IN_PROGRESS DELETION request
   - When a manager or admin approves
   - Then the person is deleted or anonymised as in S-03 and the request becomes COMPLETED
4. **Reject with reason**
   - Given a RECEIVED or IN_PROGRESS request
   - When a manager or admin sets REJECTED without a reason of 3 to 500 characters (trimmed)
   - Then it is rejected with a reason-required error; with a valid reason it becomes REJECTED
5. **Role limit**
   - Given a consultant
   - When they try to change a request's status
   - Then it is rejected with a permission error (consultants can only log requests)
6. **Overdue**
   - Given a request older than 30 days still RECEIVED or IN_PROGRESS
   - When the daily job runs
   - Then it is flagged overdue
7. **Every request logged**
   - Given any request action
   - When it happens
   - Then an audit entry records who did it and when
