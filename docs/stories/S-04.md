# S-04 - Data subject requests

**Priority:** Should  
**Requirement:** S-04 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a person whose data is stored, I want to request access, correction or deletion and have the request tracked, so that my KVKK rights are met.

## Acceptance criteria

1. **Log a request**
   - Given a person record
   - When an admin logs a request of type ACCESS, CORRECTION or DELETION with received date
   - Then it is saved with status OPEN and a due date 30 days later
2. **Complete access**
   - Given an OPEN ACCESS request
   - When the admin triggers an export
   - Then a file with the person's data is produced and the request becomes DONE with the date
3. **Deletion**
   - Given an OPEN DELETION request
   - When the admin approves
   - Then the person is deleted or anonymised as in S-03 and the request becomes DONE
4. **Overdue**
   - Given a request older than 30 days still OPEN
   - When the daily job runs
   - Then it is flagged overdue
5. **Every request logged**
   - Given any request action
   - When it happens
   - Then an audit entry records who did it and when

## Dependencies

S-03, A-12

## Open questions

Request intake channel (e-mail to the firm assumed; self-service portal later). Request statuses OPEN, DONE, REJECTED are ASSUMPTION; 30-day deadline follows the usual KVKK response period.
