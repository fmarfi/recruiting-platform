# A-08 - Account timeline

**Priority:** Should  
**Requirement:** A-08 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a consultant, I want one chronological view of everything that happened for an account, so that I can prepare a client call in a minute.

## Acceptance criteria

1. **Contains all event kinds**
   - Given an account with a status change, an activity, a proposal change, a job order change and a candidate move
   - When the timeline is opened
   - Then all five appear, newest first, each with type, summary, user and time
2. **Reason shown**
   - Given a status change that had a reason
   - When the timeline is viewed
   - Then the reason is shown with the entry
3. **Filter by kind**
   - Given a timeline with mixed events
   - When the user filters to ACTIVITY only
   - Then only activities remain
4. **Complete and consistent**
   - Given any legal status change
   - When it happens
   - Then a timeline entry exists from the same transaction, so a failed change leaves no entry and a successful one never lacks it
5. **Pagination**
   - Given an account with 200 events
   - When the timeline loads
   - Then the first page is returned in under 2 seconds and older events load on request
