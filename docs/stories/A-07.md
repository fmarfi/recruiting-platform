# A-07 - Candidate pipeline per job order

**Priority:** Must  
**Requirement:** A-07 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a consultant, I want to track each candidate's stage on a job order with a rejection reason, so that the whole search is visible.

## Acceptance criteria

1. **Add a candidate by hand**
   - Given an open job order and a person of type CANDIDATE
   - When the user adds them
   - Then an application exists in stage SOURCED
2. **No duplicates**
   - Given a person already on the job order
   - When the user adds them again
   - Then it is rejected with a pointer to the existing application
3. **Move forward**
   - Given an application in SOURCED
   - When the user moves it to PRESENTED
   - Then the stage changes (skipping SCREENED is allowed) and the move is logged
4. **Rejection needs a reason**
   - Given an application in SCREENED
   - When the user moves it to REJECTED without a reason
   - Then it is rejected; with a reason the reason is stored and shown on the card
5. **Placed only from offer**
   - Given an application in SCREENED
   - When the user moves it to PLACED
   - Then it is rejected; from OFFER it succeeds
6. **Reinstate**
   - Given an application in REJECTED
   - When the user moves it to SCREENED
   - Then the stage changes and the old reason stays in history
7. **Same person, two jobs**
   - Given a person on job order X
   - When they are added to job order Y of another account
   - Then both applications exist independently
8. **Closed job order**
   - Given a FILLED job order
   - When a user adds or moves a candidate
   - Then it is rejected
