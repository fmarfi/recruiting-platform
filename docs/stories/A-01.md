# A-01 - Client accounts and overview

**Priority:** Must  
**Requirement:** A-01 in `docs/requirements.md`  
**Status:** Proposed (until the client validates)

## User story

As a consultant, I want one account per client company and an overview of all accounts filterable by status, so that I see every client in one place.

## Acceptance criteria

1. **Create an account**
   - Given a signed-in consultant
   - When they create an account with name, sector and responsible consultant
   - Then the account exists with status LEAD, is listed in the overview, and the creation is logged
2. **Name is mandatory**
   - Given the create form
   - When name is empty
   - Then the account is not saved and a field error names the missing field
3. **Duplicate name**
   - Given an account named "Atlas Retail" exists
   - When a user creates another account with the same name (case-insensitive)
   - Then the system rejects it and shows a link to the existing account
4. **Filter by status**
   - Given accounts in several statuses
   - When the user filters the overview by ACTIVE
   - Then only ACTIVE accounts are listed, and the count matches
5. **Overview shows all**
   - Given 10 accounts exist
   - When the user opens the account list without filters
   - Then all 10 are shown with name, sector, status badge, owner (paginated if more than the page size)

## Dependencies

Authentication and roles (NFR-05)

## Open questions

Which fields beyond name, sector and owner are needed (size, city, tax number)? Can one company have several legal entities?
